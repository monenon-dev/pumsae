# 배포 가이드

배포 명령은 이 저장소에서 실행하지 않습니다. Vercel·Railway 콘솔에서 GitHub 저장소를 연결하면 `main`에 푸시할 때마다 자동으로 배포됩니다.

권장 순서: **Neon DB → Railway(백엔드) → Vercel(프론트) → CORS에 Vercel URL 반영**.

관련 문서: [프로젝트 개요](./프로젝트.md) · [데이터 ERD](./erd.md)

---

## Railway (FastAPI)

1. New Project → GitHub 저장소 연결
2. **Root Directory**를 `backend`로 지정합니다. (`backend/Dockerfile` 사용)
3. 아래 환경변수를 Variables에 넣습니다.
4. 배포 후 Public Domain을 켜고 URL을 복사합니다. (예: `https://pumsae-api.up.railway.app`)

`backend/Dockerfile`은 Python 3.12 이미지에 `requirements.txt`를 설치하고 `playwright install --with-deps chromium`을 실행합니다. 시작 명령은 `backend/railway.toml`에 있습니다.

```text
sh -c 'alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}'
```

헬스 체크 경로: `GET /health`

### Railway 환경변수

| 변수 | 필수 | 값 |
|---|---|---|
| `DATABASE_URL` | 예 | Neon Postgres connection string. `postgres://`, `postgresql://`, `postgresql+psycopg://` 형식 모두 psycopg2로 맞춰 씁니다 |
| `JWT_SECRET` | 예 | access token용 긴 랜덤 문자열. 로컬 `change-me` 쓰지 말 것 |
| `JWT_REFRESH_SECRET` | 예 | refresh token용. `JWT_SECRET`과 **다른** 값 |
| `R2_ACCOUNT_ID` | 예 | Cloudflare 계정 ID |
| `R2_ACCESS_KEY_ID` | 예 | R2 API 토큰 액세스 키 |
| `R2_SECRET_ACCESS_KEY` | 예 | R2 API 토큰 시크릿 |
| `R2_BUCKET_NAME` | 예 | 버킷 이름 |
| `R2_PUBLIC_URL` | 예 | 이미지가 브라우저에 열리는 공개 주소. 예: `https://pub-xxxxxxxx.r2.dev` (끝에 `/` 없이). 없으면 업로드 API가 503 |
| `CORS_ORIGINS` | 예 | Vercel 프론트 URL. 쉼표로 여러 개 가능. 끝에 `/` 없이. 예: `https://pumsae.vercel.app,http://localhost:3000` |
| `COOKIE_SECURE` | 권장 | `true`. HTTPS에서 refresh 쿠키가 `SameSite=None; Secure`로 나가 Vercel↔Railway 교차 사이트에서도 로그인이 유지됨 |
| `JWT_ACCESS_TTL_MINUTES` | 선택 | access token 수명(분). 기본 15 |
| `JWT_REFRESH_TTL_DAYS` | 선택 | refresh token 수명(일). 기본 14 |

## Vercel (Next.js)

1. New Project → 같은 GitHub 저장소 연결
2. Root Directory는 저장소 **루트** (Next.js `app/`이 있는 위치)
3. Framework Preset: Next.js
4. 환경변수:

| 변수 | 필수 | 값 |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | 예 | Railway 공개 URL. 끝에 `/` 없이. 예: `https://pumsae-api.up.railway.app` |
| `NEXT_PUBLIC_SITE_URL` | 권장 | Vercel 프론트 URL. OG 이미지 절대경로와 편집기의 주소 표시에 사용. 예: `https://pumsae.vercel.app` |

프론트 URL이 나온 뒤 Railway `CORS_ORIGINS`에 그 주소를 넣고 백엔드를 한 번 재배포하세요.

체험 신청 실시간 알림은 `NEXT_PUBLIC_API_URL`의 `https`를 `wss`로 바꿔 WebSocket에 붙습니다. 토큰은 주소가 아니라 연결 후 첫 메시지로 보냅니다.

## 모바일 앱 (Flutter)

API 주소는 빌드할 때 넣습니다.

```bash
cd pumsae_app
flutter build apk --dart-define=API_BASE_URL=https://pumsae-api.up.railway.app
```

`API_BASE_URL`이 없으면 개발용 주소(Android 에뮬레이터 `10.0.2.2:8000`, 그 외 `localhost:8000`)를 씁니다.

## 마이그레이션 (`alembic upgrade head`)

**배포할 때마다 자동으로 실행됩니다.** 시작 명령이 `backend/railway.toml`에 있고, 이 파일의 설정은 Railway 대시보드의 Start Command보다 우선합니다.

- 새 리비전은 `backend/alembic/versions/`에 추가합니다.
- 마이그레이션이 실패하면 새 컨테이너가 뜨지 않고, Railway는 이전 배포를 계속 서비스합니다. Deploy Logs에서 `Running upgrade …` 줄과 에러를 확인하세요.
- 새 컬럼·테이블이 필요한 코드를 배포할 때는, 배포 전에 운영 DB에 먼저 마이그레이션을 적용하면 가장 안전합니다(기존 코드는 새 컬럼이 있어도 동작합니다).

수동으로 실행해야 할 때:

```bash
cd backend
# backend/.env 의 DATABASE_URL 이 대상 DB를 가리키는지 먼저 확인
alembic current
alembic upgrade head
```

또는 Railway 대시보드 → 백엔드 서비스 → Shell에서 `alembic upgrade head`.
